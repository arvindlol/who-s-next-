# Changelog

## 0.2.0 — Unified version (2026-11-13)

Backup of the code before these changes: `D:\Internship\who-s-next--main\who-s-next--main_backup_2026-11-11`.

### Merge resolved
- `App.jsx` and `Candidates.jsx` no longer contain merge-conflict markers; the app builds again.
- Candidates page: piyush-dev's UI (CSV import/export, board view, bulk actions, undo, ratings, timeline, quick emails) on the backend's resume-storage contract, plus arvind-dev's `?new=true&returnTo=` flow and a `skills` field.
- The candidates stylesheet lost in the add/add conflict is restored as `pages/Candidates.css` (exact-case name), with its global rules (`.btn--danger`, mobile `.modal__actions`) scoped to the candidates page.
- Pages split into components: `pages/candidates/*`, shared `AppLayout`, `PasswordInput`, `ScreeningReportView`.

### Fixed
- Resumes saved by the old Candidates page could never be screened (wrong field and path). One resume format now: `resumePath`/`resumeUrl`/`resumeName`, path `resumes/{uid}/{candidateId}-{timestamp}-{file}.pdf`; old documents are read correctly and converted by the migration script.
- Activity timeline, feedback and bulk stage changes were blocked by the Firestore rules; an append-only `activity` rule now allows them.
- PDF-only everywhere (upload UI, Storage rules, backend) — DOC/DOCX/TXT uploads used to be accepted and then fail at screening.
- Dashboard "interviews pending" was always 0 and Home job cards always showed 0 candidates (wrong status and a `matches` collection nothing wrote to).
- Interview status `plan_approved` was shown as step 1; one shared status vocabulary is now used everywhere.
- Signing up saved the email prefix instead of the full name; `Auth.jsx` now goes through the auth context. Password placeholder matches the 6-character rule. Added "Forgot password?".
- Plan review always said "Draft, not approved"; it now reflects the real state and hides Approve after approval.
- Regenerating a plan silently cancelled an approval and two parallel generations could collide; generation is now locked, versioned in a transaction and needs explicit confirmation to replace an approved plan.
- "Already advanced" was keyed by screening ID while interviews are per job + candidate; both now use job + candidate. A new screening refreshes the link of a not-yet-approved interview.
- Error messages now show the server's specific reason instead of misleading generic text.
- The email field no longer appends `@gmail.com` silently (suggestions remain).
- Job "Delete permanently" only hid the job; it now really deletes the file, screenings, interviews and reports.
- `.gitignore` was a Python template that ignored every `lib/` folder; replaced with a Node/Firebase one.

### Added
- Transcript step (Firestore-backed): paste or import `.txt`/`.vtt`/`.srt`, speaker mapping, server-side email/phone redaction.
- Final report generated by Gemini against the approved plan: per-question scores, quotes verified against the transcript, area and overall scores computed on the server, AI suggestion, evidence strength.
- Hiring decisions saved on the server with history; the candidate's stage follows the workflow (advanced → Interview Pending, approved → Interview Ready, decision → Offer / Interview Pending / Rejected).
- Reports list page (filterable by job and decision); old report URLs redirect.
- Editing interview questions before approval (wording, answer guide, follow-up, red flag, minutes, order, removal).
- Screening 1–5 candidates (was exactly 2–3) with real progress stages instead of a timer.
- Interview rounds: after "Another interview", advancing again starts round 2.
- Account deletion; full candidate/job erasure with an 8-second undo for candidates and a daily clean-up job.
- Privacy notes about Gemini data use on the Screening and Profile pages.
- Gemini mock mode for the emulator; Firebase emulator configuration; `frontend/.env.example`, `functions/.env.example`.

### Security
- Gemini keys are encrypted with a key from Secret Manager (`GEMINI_KEY_ENCRYPTION_KEY`) instead of a key stored next to them in Firestore; old keys keep working and are upgraded on use or by the migration script.
- Per-user rate limits for key checks, screenings, plans and reports.
- Optional App Check (frontend provider + `ENFORCE_APP_CHECK` for functions).
- Firestore rules validate field names, types and sizes; owner and file paths can't be changed.
- Prompts use `systemInstruction` and mark documents and recruiter text as untrusted data (prompt-injection hardening).
- Diagnostics and rate-limit records carry `expireAt` for TTL clean-up.

### AI reliability
- Structured output (`responseSchema`) for every Gemini call.
- Inconsistent responses are repaired instead of rejected: scores, labels, ranks, summary counts, question numbering, minute totals and topic coverage are computed on the server. One automatic retry with a correction note when a response is structurally unusable.
- Large PDF sets go through the Gemini Files API instead of inline data.
- Blocked or truncated Gemini responses produce clear messages.
- Screening findings are passed into the interview-plan prompt. Model IDs are configurable.

### Developer experience
- Backend split into `src/lib` (pure, unit-tested), `src/gemini`, `src/services`, `src/handlers`.
- Unit tests with Node's built-in runner: `functions` (26 tests) and `frontend` (13 tests).
- ESLint config for the frontend; lazy-loaded routes.
- Removed dead code (`data/screeningDemo.js`, the hardcoded mock report, Vite temp file, empty root lockfile).
- One-off migration script `functions/scripts/migrate-v2.js` (dry run by default).
